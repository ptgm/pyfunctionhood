# Experiments

Scripts, raw data and figures for the experiments reported in the *Implementation* section of
**"On Exploring the Vicinity of Monotone Boolean Functions"** (Tenera Roxo, Manquinho, Monteiro),
an extension of the CMSB 2025 paper
[*Computation of Immediate Neighbours of Monotone Boolean Functions*](https://doi.org/10.1007/978-3-032-01436-8_1).

They evaluate the algorithms that compute the **closest parents and children of a monotone Boolean
function in a different signature** (`HasseDiagram.get_f_parents_with_sign_changes` and
`HasseDiagram.get_f_children_with_sign_changes` in the library), and use only the public API of the released package.
This directory belongs to the GitHub repository only: it is **not** part of the package distributed on PyPI.

## Contents

| File | Description |
|------|-------------|
| `fig_sc_cost.py` | Average time per call of the closest-parents / closest-children algorithms, versus the number *k* of simultaneous sign changes (Figure `fig_sc_cost`). |
| `fig_sc_neighbourhood.py` | Size of the neighbourhood of a function across signatures, versus *k* (Figure `fig_sc_neighbourhood`). |
| `fig_sc_cost.pdf`, `fig_sc_cost.png` | Figure generated by `fig_sc_cost.py` from the data in `results/`. |
| `fig_sc_neighbourhood.pdf`, `fig_sc_neighbourhood.png` | Figure generated by `fig_sc_neighbourhood.py` from the data in `results/`. |
| `results/` | Raw data, one tab-separated file per point (*n*, *k*) and experiment (about 30 MB in total). |
| `requirements.txt` | Python dependencies. |

## Requirements

Python 3.9 or later. The results were produced with `pyfunctionhood` **0.3.0**:

```bash
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

`requirements.txt` installs `pyfunctionhood==0.3.0` (which brings in `bitarray`) and `matplotlib`.

## Regenerating the figures from the data

The data are in `results/`, so the figures can be redrawn without recomputing anything:

```bash
python fig_sc_cost.py
python fig_sc_neighbourhood.py
```

Each command reads `./results` and writes the `.pdf` and `.png` files in the current directory.

## Recomputing the data

Both scripts accept `--run`, which computes the points that are **missing** from `results/` and then plots.
Existing point files are never overwritten unless `--force` is given, so an interrupted run can simply be restarted.

```bash
# the runs behind the figures of the paper (on a 32-core server, 30 processes)
python fig_sc_cost.py          --run --samples 10 --reps 10 --batch 10 --nmax 8 --workers 30
python fig_sc_neighbourhood.py --run --nmax 8 --workers 30
```

Useful variants:

```bash
python fig_sc_cost.py --run --workers 4                    # on 4 processes
python fig_sc_neighbourhood.py --run --nmax 7              # skip n = 8, by far the slowest
python fig_sc_cost.py --run --n 6 --k 3 4 --force          # recompute only the points (n=6,k=3) and (n=6,k=4)
python fig_sc_cost.py --data my_results --out my_figures   # use another data / output directory
```

Common options: `--data DIR` (data directory, default `results`), `--out DIR` (figure directory),
`--nmax N` (dimensions 2..N, default 8), `--n ...` and `--k ...` (restrict the points, with `--run`),
`--workers W` (processes, default 2). Run either script with `--help` for the full list.

Do not use more workers than physical cores: the first experiment measures running times.

## What is measured

For each dimension *n*, functions are sampled by random walks from the infimum to the supremum of the poset of
non-degenerate monotone functions, through same-signature parents. The walks are seeded by `(n, sample)`, so every
point (*n*, *k*) is evaluated on the very same functions. *k* = 0 is the baseline: the same-signature algorithms
of the CMSB 2025 paper, run on the same functions.

* **`fig_sc_cost.py`**: at every visited function, `--reps` random sets of *k* sign changes are drawn, and each
  measurement is the mean time of `--batch` consecutive calls (a single call lasts only microseconds).
  Defaults: 10 random walks per dimension, 10 sets *K* per function and *k*, batches of 10 calls.
* **`fig_sc_neighbourhood.py`**: at every visited function, **all** sets *K* of *k* sign changes are enumerated,
  recording whether a closest parent / child exists in the corresponding target signature and how many there are.
  Defaults: 100 random walks for *n* ≤ 6, 40 for *n* = 7 and 20 for *n* = 8 (`--samples N` uses *N* for every *n*).
  The *n* = 8 runs take about a minute per walk.

## Data format

One file per point, written atomically when the point is complete. The parameters are part of the file name, so
changing them computes new points instead of silently reusing old ones.

* `results/n<n>_k<k>_s<samples>_r<reps>_b<batch>.txt` (cost). Tab-separated columns:
  `sample, n, level, k, rep, t_parents, n_parents, t_children, n_children`.
* `results/neigh_n<n>_k<k>_s<samples>.txt` (neighbourhood). Tab-separated columns, one row per visited function:
  `sample, n, step, k, n_signatures, p_exists, n_parents, c_exists, n_children`.

The columns are described in the docstring at the top of each script.

## Hardware

The reported measurements were taken on a 32-core server (Intel Xeon Silver 4110 @ 2.10 GHz), with 30 processes in
parallel (one core each). Running times depend on the machine, but the trends between points do not.
